---

## 一、版本号规则

| 层级 | 格式 | 含义 | 何时升版 |
|------|------|------|----------|
| **大版本** | `v{N}.x` | 产品代际 / 架构代际（如 Electron → Next.js → 移动端平台） | 架构换代、平台能力边界变化 |
| **小版本** | `v{N}.{M}` | 一轮**可验收**的交付（功能 + 文档 + 必要联调） | 完成该节「交付标准」全部勾选 |
| **补丁** | `v{N}.{M}.{P}` | 缺陷修复、文档勘误、选择器微调（**不新增**路线图任务项） | 不改变小版本任务范围 |

**状态图例**：`✅ 已发布` · `🔄 进行中` · `📝 计划中` · `📦 已归档`

**任务编号**：`{小版本}-{序号}`，例如 `2.2-03` 表示 v2.2 第 3 项任务。

| 2.3-05 | 配置项 | 站点 URL、本地文件路径、`PLAYWRIGHT_HEADED` | 📝 |

**业务流程**：

| 步骤 | 动作 |
|:----:|------|
| 1 | 打开 91 仓库站点 |
| 2 | 点击「导入」入口 |
| 3 | 进入「无卡密」 |
| 4 | 点击「上传模板」 |
| 5 | `input[type=file]` 上传 **`汇总_资源`** |
| 6 | DOM 校验成功；失败 → `__JOB_STEP__` error + Report error |

**v2.3 交付标准**：工作台一键运行成功上传；步骤进度可见；失败可 Report error。
