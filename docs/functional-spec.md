## 2. 模块详述

### 2.1 数据采集模块

#### 2.1.1 功能概述

负责自动采集闲鱼店铺和商品的运营数据，包括售出数量、浏览量、想要人数等关键指标。

#### 2.1.2 功能流程

```
[用户] → 选择数据源（Excel/手动输入）
    ↓
[系统] → 通过 Playwright 访问闲鱼链接
    ↓
[系统] → 等待页面加载完成
    ↓
[系统] → 提取目标数据元素
    │
    ├── 店铺简介 → 正则匹配 "卖出X件宝贝"
    ├── 浏览数据 → 提取 "X浏览" 文本
    ├── 想要数据 → 提取 "X人想要" 文本
    └── 商品描述 → 获取描述文本
    ↓
[系统] → 数据格式化与清洗
    ↓
[系统] → 输出到 Excel / 存入数据库
```

#### 2.1.3 核心接口

| 接口 | 说明 | 对应代码 |
|------|------|---------|
| `getIntroText(page)` | 获取店铺简介文本，包含卖出件数 | `modules/shop_data/shop_data.js` |
| `getReviewAndWantNumber(page)` | 获取浏览量和想要数 | `modules/shop_data/shop_data.js` |
| `getLinkDescription(page)` | 获取商品链接描述 | `modules/shop_data/shop_data.js` |
| `getUserName(page)` | 获取卖家昵称 | `modules/shop_data/shop_data.js` |
| `getImageUrls(page)` | 获取媒体资源 URL | `modules/shop_data/shop_data.js` |

#### 2.1.4 数据处理

```
输入数据格式（Excel）：
  ┌──────────┬──────────────────────────┐
  │  店铺名   │        店铺网址           │
  ├──────────┼──────────────────────────┤
  │  店铺A   │ https://www.goofish.com/... │
  │  店铺B   │ https://www.goofish.com/... │
  └──────────┴──────────────────────────┘

输出数据格式（Excel）：
  ┌──────────┬──────────┬──────────┬────────────┐
  │  店铺名   │ 卖出宝贝  │  日期    │  店铺网址   │
  ├──────────┼──────────┼──────────┼────────────┤
  │  店铺A   │   520    │2026/5/11 │  https://...│
  │  店铺B   │   128    │2026/5/11 │  https://...│
  └──────────┴──────────┴──────────┴────────────┘
```

#### 2.1.5 任务脚本

| 脚本 | 功能 | 数据来源 |
|------|------|---------|
| `tasks/get_shop_review_data.js` | 采集店铺每日售出数据 | `input/汇总_店铺.xlsx` |
| `tasks/get_shop_link_date_data.js` | 获取店铺链接日期数据 | 输入文件 |

### 2.2 搜索监控模块

#### 2.2.1 功能概述

支持按关键词在闲鱼平台搜索商品，提取搜索结果中的店铺链接和商品数据，支持分页遍历。

#### 2.2.2 功能流程

```
[用户] → 输入关键词
    ↓
[系统] → 访问闲鱼搜索页
    ↓
[系统] → 提取搜索结果中的商品卡片
    │
    ├── 商品标题
    ├── 商品链接
    ├── 卖家信息
    └── 价格信息
    ↓
[系统] → 翻页继续采集（可选）
    ↓
[系统] → 数据去重与清洗
    ↓
[系统] → 输出结果
```

#### 2.2.3 核心接口

| 接口 | 说明 | 对应代码 |
|------|------|---------|
| `gotoNextPage(page)` | 翻页到下一页搜索结果 | `modules/shop_data/shop_data.js` |
| `extractItemId(url)` | 从 URL 提取商品 ID | `modules/shop_data/shop_data.js` |

#### 2.2.4 任务脚本

| 脚本 | 功能 |
|------|------|
| `tasks/search_shop_links_by_keyword.js` | 按关键词搜索并提取店铺链接 |
| `tasks/get_shop_links.js` | 获取指定店铺的所有商品链接 |

### 2.3 聊天客服模块

#### 2.3.1 功能概述

管理闲鱼买家聊天会话，支持自动回复功能，提升客服响应效率。

#### 2.3.2 功能流程

```
自动回复流程：
[系统] → 获取新聊天会话列表
    ↓
[系统] → 进入每个未读会话
    ↓
[系统] → 提取买家最新消息
    ↓
[系统] → 匹配预设关键词规则
    │
    ├── 匹配成功 → 发送预设回复
    └── 匹配失败 → 标记待人工处理
    ↓
[系统] → 记录回复日志

聊天链接获取流程：
[系统] → 访问飞书或闲鱼聊天列表
    ↓
[系统] → 提取所有活跃会话链接
    ↓
[系统] → 输出到文件
```

#### 2.3.3 核心接口

| 接口 | 说明 | 对应代码 |
|------|------|---------|
| `goToChatPage(page)` | 跳转到聊天窗口 | `modules/shop_data/shop_data.js` |

#### 2.3.4 任务脚本

| 脚本 | 功能 |
|------|------|
| `tasks/auto_chat_link.js` | 自动处理聊天链接 |
| `tasks/auto_reply.js` | 根据关键词预设自动回复买家 |
| `tasks/get_feishu_chat_links.js` | 从飞书获取聊天会话链接 |

#### 2.3.5 自动回复规则配置

```json
{
  "reply_rules": [
    {
      "keywords": ["价格", "多少钱", "怎么卖"],
      "reply": "亲，价格已标注哦，具体可以看商品详情页～"

    {
      "keywords": ["包邮", "邮费", "运费"],
      "reply": "本店满XX包邮，不满邮费X元哦～"
    },
    {
      "keywords": ["库存", "有货", "还有吗"],
      "reply": "有的亲，可以直接拍下哦～"
    }
  ],
  "default_reply": "亲，欢迎咨询！有什么可以帮助您的？"
```

### 2.4 发布管理模块

#### 2.4.1 功能概述

支持将商品链接批量发布到闲鱼平台，管理发布记录，防止重复发布。

#### 2.4.2 功能流程

```
[用户] → 准备发布数据（商品信息+图片）
    ↓
[系统] → 加载发布记录，检查是否已发布
    │
    ├── 已发布 → 跳过
    └── 未发布 → 继续发布流程
    ↓
[系统] → 通过 Playwright 执行发布操作
    │
    ├── 填写商品信息
    ├── 上传图片（可选）
    ├── 设置价格和描述
    └── 提交发布
    ↓
[系统] → 记录发布结果
    ↓
[系统] → 更新发布记录文件
```

#### 2.4.3 数据存储

发布记录存储在 `store/publish_records.json.example`，格式如下：

```json
[
  {
    "id": "1234567890",
    "title": "商品标题",
    "url": "https://www.goofish.com/...",
    "publish_time": "2026-05-11T10:00:00Z",
    "status": "success"
  }
]
```

#### 2.4.4 任务脚本

| 脚本 | 功能 |
|------|------|
| `tasks/publish_links.js` | 批量发布商品链接到闲鱼 |

### 2.5 系统管理模块

#### 2.5.1 定时任务管理

**功能描述**：支持添加、编辑、删除定时任务，使用 cron 表达式控制执行时间。

**数据存储**：使用 `electron-store` 持久化（Web 方案将迁移到 SQLite/JSON 文件）。

**任务调度器**：基于 `node-cron` 实现，支持以下操作：

| 操作 | 说明 | IPC 事件 |
|------|------|---------|
| 获取可用任务列表 | 返回所有可执行的脚本列表 | `get-available-tasks` |
| 获取已保存的定时任务 | 返回已配置的定时任务列表 | `get-scheduled-tasks` |
| 添加定时任务 | 新增一个定时任务 | `add-scheduled-task` |
| 更新定时任务 | 修改已有定时任务配置 | `update-scheduled-task` |
| 删除定时任务 | 移除定时任务并停止调度 | `delete-scheduled-task` |
| 立即执行 | 手动触发任务立即执行 | `run-script` |
| 启用/停用 | 切换任务启用状态 | `toggle-task` |

**cron 表达式示例**：

| 表达式 | 说明 |
|--------|------|
| `0 8 * * *` | 每天早上 8 点执行 |
| `*/30 * * * *` | 每 30 分钟执行一次 |
| `0 0,12 * * *` | 每天 0 点和 12 点执行 |
| `0 0 * * 1` | 每周一 0 点执行 |

#### 2.5.2 任务日志

**功能描述**：记录每个任务的执行历史，包括开始时间、结束时间、状态和输出内容。

**日志存储**：最多保留 200 条日志记录，自动滚动删除旧日志。

**日志字段**：

| 字段 | 说明 |
|------|------|
| id | 唯一标识 |
| scriptPath | 执行的脚本路径 |
| startTime | 开始时间 |
| endTime | 结束时间 |
| status | running / success / failed |
| output | 执行输出文本 |

#### 2.5.3 数据导出

**功能描述**：将采集的数据导出为标准 Excel 文件（.xlsx）。

**导出工具**：`utils/file.js` 中的 `exportToExcelFile()` 函数。

**输出目录结构**：
```
output/
└── YYYY-MM-DD/
    └── 店铺每日售出数据/
        └── 店铺每日售出数据_YYYY-MM-DD.xlsx
```

## 3. 浏览器引擎层设计

### 3.1 概述

浏览器引擎层是系统的核心基础设施，基于 Playwright 框架，负责所有与闲鱼平台的浏览器交互操作。

### 3.2 Browser 类（`utils/browser.js`）

#### 3.2.1 功能职责

- 管理浏览器实例的生命周期（启动、连接、关闭）
- 提供容错机制（页面失效自动重建、导航重试）
- 支持两种运行模式：独立启动 和 CDP 连接已有浏览器

#### 3.2.2 运行模式

**模式一：连接本机 Chrome（推荐）**

```
┌─────────────┐         CDP           ┌──────────────┐
│  本机 Chrome  │ ←─────────────────→ │  Playwright   │
│  (端口 9222)  │     localhost:9222   │  自动化脚本   │
└─────────────┘                       └──────────────┘
```

- 优点：复用本机登录态，无需重复登录
- 前提：Chrome 需以远程调试模式启动 (`start_chrome.bat`)

**模式二：Playwright 独立启动**

```
┌──────────────┐     launch      ┌─────────────┐
│  Playwright   │ ─────────────→ │  Chromium    │
│  自动化脚本   │                │  (无头/有头)  │
└──────────────┘                └─────────────┘
```

- 优点：无需额外配置，自动管理浏览器
- 缺点：需要单独处理登录态

#### 3.2.3 容错机制

```
页面导航失败
    ↓
检查页面状态 → 页面已关闭 → 重建页面
    ↓                     ↓
页面有效         上下文无效 → 重建上下文
    ↓                     ↓
重试导航         浏览器无效 → 重建浏览器
    ↓
达到最大重试次数 (30次) → 抛出异常
```

#### 3.2.4 核心方法

| 方法 | 功能 | 错误处理 |
|------|------|---------|
| `connectToExistingBrowser(port)` | 连接本机 Chrome | 失败后自动回退到 `launchBrowser()` |
| `navigateWithRetry(url)` | 导航并自动重试 | 页面/上下文/浏览器逐级重建 |
| `ensurePageValid(url)` | 检查页面状态 | 失效时自动恢复 |
| `recreateContext()` | 重建浏览器上下文 | 清理旧上下文 |
| `recreateBrowser()` | 重建浏览器实例 | 清理旧实例 |

## 5. 目标架构（Next.js 全栈方案）

### 5.1 架构总览

```
┌───────────────────────────────────────────────────────────┐
│                       Next.js 应用                        │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                   前端页面层                          │  │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────────────┐    │  │
│  │  │ 仪表盘页  │ │ 任务管理  │ │ 数据看板 / 日志  │    │  │
│  │  └────┬─────┘ └────┬─────┘ └────────┬─────────┘    │  │
│  └───────┼────────────┼────────────────┼──────────────┘  │
│          │            │                │                  │
│  ┌───────┴────────────┴────────────────┴──────────────┐  │
│  │              API Routes (Serverless)                 │  │
│  │  ┌──────┐ ┌───────┐ ┌──────┐ ┌─────┐ ┌─────────┐  │  │
│  │  │ 任务  │ │ 定时   │ │ 数据  │ │ 日志 │ │ 设置    │  │  │
│  │  │ /api  │ │ /api  │ │ /api  │ │ /api│ │ /api    │  │  │
│  │  │/tasks │ │/sche- │ │/ex-  │ │/logs│ │/settings│  │  │
│  │  │       │ │dules  │ │ports  │ │     │ │         │  │  │
│  │  └──┬───┘ └───┬───┘ └──┬───┘ └──┬──┘ └────┬────┘  │  │
│  └─────┼─────────┼────────┼────────┼──────────┼───────┘  │
│        │         │        │        │          │           │
│  ┌─────┴─────────┴────────┴────────┴──────────┴───────┐  │
│  │                  核心服务层                          │  │
│  │  ┌──────────┐ ┌────────┐ ┌───────┐ ┌────────────┐  │  │
│  │  │ 任务调度   │ │ Play-  │ │ 数据   │ │ WebSocket  │  │  │
│  │  │ (node-   │ │wright  │ │ SQLite │ │ (SSE)      │  │  │
│  │  │  cron)   │ │ 引擎    │ │        │ │            │  │  │
│  │  └──────────┘ └────────┘ └───────┘ └────────────┘  │  │
│  └─────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────┘
```

**关键设计理念**：
- **全栈统一**：Next.js 同时承载前后端，减少通信开销
- **API Routes**：利用 Next.js API Routes 替代独立后端服务
- **Server-Sent Events (SSE)**：替代 WebSocket，更轻量的实时推送方案
- **组件即页面**：React 组件直接映射到页面路由

### 5.2 页面路由设计

| 路由路径 | 页面 | 功能 | API 路由 |
|---------|------|------|---------|
| `/` | 仪表盘 | 任务统计、系统状态 | `GET /api/dashboard` |
| `/tasks` | 任务管理 | 任务列表、手动执行 | `GET /api/tasks`, `POST /api/tasks/run` |
| `/schedules` | 定时任务 | CRUD 配置 | `GET/POST/PUT/DELETE /api/schedules` |
| `/logs` | 任务日志 | 历史记录查询 | `GET /api/logs`, `DELETE /api/logs` |
| `/data` | 数据看板 | 趋势图表、导出 | `GET /api/exports` |
| `/settings` | 系统设置 | 浏览器、存储配置 | `GET/PUT /api/settings` |
| `/api/sse` | - | SSE 实时推送 | `GET /api/sse` |

### 5.3 API 路由清单

| 方法 | 路径 | 说明 |
|------|------|------|

### 5.4 实时推送方案（SSE）

采用 Server-Sent Events 替代传统 WebSocket，更符合 Next.js 无服务器架构：

```
浏览器 ← 持续 HTTP 连接 ← Next.js API Route (sse.ts)

事件流格式：
event: task:started
data: {"taskId":"xxx","name":"店铺数据采集"}

event: task:output
data: {"taskId":"xxx","output":"正在采集第10个店铺..."}

event: task:completed
data: {"taskId":"xxx","status":"success","duration":3200}

event: task:failed
data: {"taskId":"xxx","status":"failed","error":"浏览器连接超时"}
```

## 6. 错误处理机制

### 6.1 浏览器层错误处理

```
错误类型：
├── 页面关闭 (Page closed)
│   └── 处理：自动重建页面
├── 上下文关闭 (Context closed)
│   └── 处理：自动重建上下文和页面
├── 浏览器崩溃 (Browser crashed)
│   └── 处理：自动重建整个浏览器环境
├── 导航超时 (Navigation timeout)
│   └── 处理：重试导航（最多30次）
├── 元素未找到 (Element not found)
│   └── 处理：返回默认值/空值
└── 等待超时 (Wait timeout)
    └── 处理：跳过当前操作
```

### 6.2 数据层错误处理

```
错误类型：
├── 文件读取失败
│   └── 处理：创建默认文件/返回空数据
├── Excel 解析错误
│   └── 处理：跳过当前行并记录日志
├── 数据格式异常
│   └── 处理：正则匹配失败时使用默认值
└── 写入失败
    └── 处理：重试3次，仍失败则记录错误
```

## 8. 安全与合规

### 8.1 登录态管理

- 登录态文件（`storage-state.json`）不能提交到 Git
- 已在 `.gitignore` 中添加登录态文件路径
- 提供独立的登录操作手册（`docs/AI-handbook-xianyu-login-session.md`）

### 8.2 操作频率限制

为避免触发闲鱼风控机制，建议遵循以下操作规范：

- 两次操作之间至少间隔 1-2 秒（已通过 `sleep` 函数实现）
- 单次任务最多连续操作 100 条数据
- 批量操作时每 10 条数据保存一次中间结果
- 避免在高峰时段（如 20:00-23:00）执行大量自动化操作

### 8.3 数据隐私

- 所有数据仅存储在本地，不上传到任何远程服务器
- 不收集任何用户个人信息
- 不包含任何形式的埋点或统计分析
