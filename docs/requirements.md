> **文档版本**：v1.0
> **更新日期**：2026-05-11
> **项目状态**：从 Electron 桌面应用 → 本地 Web 方案转型中

---

## 1. 项目背景

### 1.1 业务背景

闲鱼是国内领先的二手电商平台，大量个人卖家和专业卖家在日常运营中面临以下痛点：

- **数据收集困难**：需要手动查看每个店铺的售出数据、浏览数据，耗时耗力
- **重复操作繁琐**：回复买家消息、发布商品链接等操作高度重复
- **多店铺管理不便**：运营多个店铺时，缺乏统一的监控和管理工具
- **定时任务缺失**：无法在特定时间自动执行运营操作

### 1.2 项目目标

构建一套本地化的闲鱼电商运营自动化工具，实现以下核心目标：

1. **自动化数据采集**：自动抓取店铺售出数据、商品浏览数据等运营指标
2. **智能客服辅助**：支持自动回复买家消息，提升沟通效率
3. **批量操作能力**：支持商品链接批量发布、关键词批量搜索
4. **定时任务调度**：支持按 cron 表达式配置定时执行任务
5. **数据报表导出**：将采集数据导出为 Excel 格式，便于分析和归档

| 角色 | 描述 | 核心需求 |

### 4.1 性能需求

| 需求编号 | 需求名称 | 描述 |
|---------|---------|------|
| NFR-001 | 页面加载速度 | 页面首屏加载时间 ≤ 3秒 |
| NFR-002 | 任务执行效率 | 单次数据采集任务执行时间 ≤ 5分钟（100条以内） |
| NFR-003 | 并发支持 | 支持同时运行 3 个自动化任务 |
| NFR-004 | 定时精度 | 定时任务执行误差 ≤ 10秒 |

| 需求编号 | 需求名称 | 描述 |
|---------|---------|------|
| NFR-010 | 系统可用性 | 系统应能 7×24 小时持续运行 |
| NFR-011 | 断线重连 | 浏览器断开后应自动重连并恢复任务 |
| NFR-012 | 错误恢复 | 任务执行失败后应自动重试（最多3次） |
| NFR-013 | 数据持久化 | 所有配置数据和日志应持久化存储 |

### 4.3 安全性需求

| 需求编号 | 需求名称 | 描述 |

| NFR-022 | 浏览器隔离 | 自动化操作不应影响用户正常浏览器使用 |

### 4.4 可维护性需求

| 需求编号 | 需求名称 | 描述 |

## 5. 约束条件

### 5.1 技术约束

1. **运行时**：必须使用 Node.js ≥ 18.x
2. **自动化框架**：必须使用 Playwright
3. **包管理器**：推荐使用 pnpm
4. **模块系统**：ES Modules

### 5.2 业务约束

1. **登录态**：用户需自行完成闲鱼登录，系统不处理验证码/扫码
2. **频率限制**：需合理控制操作频率，避免触发闲鱼风控机制
3. **合规使用**：用户应遵守闲鱼平台服务条款

### 5.3 部署约束

1. **本地部署**：系统为本地工具，不提供云端部署方案
2. **无用户系统**：无需多用户管理和权限控制
3. **轻量级**：尽量减少外部依赖，降低部署复杂度

P1（重要功能）：
  ├── 浏览量/想要数数据采集
  ├── 搜索结果分页遍历
  ├── 发布记录管理
  ├── 手动立即执行任务
  ├── 定时监控功能
  ├── 飞书聊天链接获取

  ├── 媒体资源自动下载
  ├── 批量打招呼
  ├── 多条件搜索过滤
  ├── 定时自动导出
  ├── 任务失败告警
  └── 发布计划排期

P3（远期规划）：
  ├── 数据可视化仪表盘
  ├── 多账号管理
  ├── 智能定价建议
  └── 竞品分析报告

## 7. 功能边界

### 7.1 系统边界（当前版本不做）

- ❌ 不处理闲鱼登录验证码、滑块验证
- ❌ 不提供云端托管服务
- ❌ 不支持多用户登录和权限管理
- ❌ 不提供移动端 App
- ❌ 不包含支付相关功能
- ❌ 不涉及闲鱼社区内容管理

### 7.2 系统边界（Web 方案新增）

- ✅ 提供 Web 管理界面替代 Electron 桌面窗口
- ✅ 支持通过浏览器访问操作界面
- ✅ RESTful API 接口设计
- ✅ 实时日志推送（WebSocket）
- ✅ 任务执行队列管理
- ✅ 数据可视化展示
