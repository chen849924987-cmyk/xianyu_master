## 二、Phase 1：架构转型（2026.05 - 2026.06）

### 目标
将 Electron 桌面应用改造为前后端分离的本地 Web 方案，剥离不必要的依赖，为核心逻辑提供统一调用接口。

| 任务编号 | 任务名称 | 预估工时 | 优先级 | 状态 |
|---------|---------|---------|-------|------|

| 1.2 | 提取任务脚本的统一执行接口 | 3天 | P0 | 📝 待开始 |
| 1.3 | 设计项目新目录结构和模块划分 | 1天 | P0 | ✅ 已完成 |

| 1.5 | 解耦登录态管理（从 Electron Store 迁移） | 2天 | P1 | 📝 待开始 |
| 1.6 | 重构 Browser 类为独立服务 | 2天 | P0 | 📝 待开始 |
| 1.7 | 编写单元测试用例（核心模块） | 3天 | P1 | 📝 待开始 |

| 风险 | 可能性 | 影响 | 应对策略 |

## 四、Phase 3：前端页面开发（2026.06 - 2026.07）

### 目标
基于 Next.js App Router + React 开发 Web 管理界面，所有页面是 Next.js 的 `app/` 目录下的 Server/Client Components。

### 3.1 技术选型

| 类别 | 选择 | 说明 |
|------|------|------|
| 全栈框架 | Next.js (App Router) | 同时承载前后端 |
| UI 框架 | React + TypeScript | 组件化开发 |
| 样式方案 | Tailwind CSS | 原子化 CSS |
| 状态管理 | React Context + useReducer | 轻量级状态管理，无需额外库 |
| 路由 | Next.js App Router (文件系统路由) | 自动路由映射 |
| 数据请求 | fetch + Server Actions | 原生 API，无需 Axios |
| 实时推送 | SSE (EventSource) | 替代 WebSocket |
| 图表 | Recharts / ECharts | 数据可视化 |
| UI 组件 | shadcn/ui + Radix | 轻量、可定制、无障碍 |

## 八、技术债务清理

在转型过程中，需要清理以下技术债务：

| 债务项 | 现状 | 目标 | 对应阶段 |
|--------|------|------|---------|
| Electron 依赖 | 主进程 + preload + 前端耦合 | 完全移除 | Phase 1 |

| 无 TypeScript | 全部 JS | 逐步引入 TypeScript | Phase 2-3 |
| 无自动化测试 | 手动测试 | 核心模块单元测试 + 集成测试 | Phase 1-4 |
| 前端样式混乱 | 内联 style + 杂乱 CSS | Tailwind CSS + 设计规范 | Phase 3 |
| Electron 前端页面耦合 | index.html + preload.js | 迁移到 Next.js React 组件 | Phase 1-3 |

## 十、开发规范

### 10.1 Git 分支策略

```
main          ─── 稳定版本，用于发布
  ├── develop     ─── 开发主分支
  │   ├── feat/phase1-*     ─── Phase 1 功能分支
  │   ├── feat/phase2-*     ─── Phase 2 功能分支
  │   ├── feat/phase3-*     ─── Phase 3 功能分支
  │   └── fix/*             ─── 修复分支
  └── release/*   ─── 发布前准备分支
```

### 10.2 Commit 规范

遵循 Conventional Commits 规范（中文描述）：

```
feat: 添加定时任务 cron 表达式校验功能
fix: 修复浏览器断开连接后页面无法重建的问题
docs: 更新 API 接口文档
refactor: 重构任务执行器，提取公共逻辑
test: 添加 Browser 类的单元测试
chore: 更新依赖版本
style: 格式化代码（不影响逻辑）
```
